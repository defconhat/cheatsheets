# 📝 Markdown — шпаргалка по синтаксису

> **Markdown** — простой текстовый формат разметки (с 2004 г., John Gruber).
> Читается как обычный текст, конвертируется в HTML.
> Используется в README, документации, GitHub, Reddit, Notion, Obsidian.

---

## 🚀 Заголовки

```markdown
# Заголовок 1 уровня (<h1>)
## Заголовок 2 уровня (<h2>)
### Заголовок 3 уровня (<h3>)
#### Заголовок 4 уровня (<h4>)
##### Заголовок 5 уровня (<h5>)
###### Заголовок 6 уровня (<h6)
```

> Заголовок 1 можно и так:
> ```markdown
> Заголовок 1
> ============
>
> Заголовок 2
> -----------
> ```

### Автоматические якоря
Большинство процессоров генерируют id для заголовков:
```markdown
## Мой заголовок
```
→ `<h2 id="мой-заголовок">` → ссылка `[перейти](#мой-заголовок)`

## ✍️ Форматирование текста

```markdown
*курсив*  или  _курсив_
**жирный**  или  __жирный__
***жирный курсив***  или  ___жирный курсив___
~~зачёркнутый~~
`код внутри строки`
под~индекс~  над^индекс^   (не везде поддерживается)
```

Результат:
*курсив* · **жирный** · ***жирный курсив*** · ~~зачёркнутый~~ · `код`

### Цитаты
```markdown
> Это цитата
> продолжается на следующей строке.
>
> > Вложенная цитата
```

> Цитата, продолжается.
>
> > Вложенная.

### Перенос строки
- Один перенос строки = пробел (в большинстве flavour'ов).
- Два пробела в конце строки или `\` = явный `<br>`.
- Пустая строка = новый абзац.

```markdown
Первая строка\
Вторая строка (явный перенос)

Новый абзац.
```

## 📋 Списки

### Маркированные (unordered)

1. Третий

```markdown

```markdown

## 🔀 Встроенный HTML

Markdown разрешает HTML внутри:
```markdown
<details>
<summary>Нажмите, чтобы развернуть</summary>

Скрытое содержимое.

</details>

<kbd>Ctrl</kbd> + <kbd>C</kbd>

<mark>подсвеченный текст</mark>

<sub>под-индекс</sub> <sup>над-индекс</sup>

<!-- HTML комментарий -->

<abbr title="HyperText Markup Language">HTML</abbr>
```

Результат:
<details>
<summary>Нажмите</summary>
Скрытое.
</details>

<kbd>Ctrl</kbd>+<kbd>C</kbd> · <mark>подсветка</mark>

## 🎨 Экранирование

Чтобы спецсимволы не интерпретировались — экранируйте `\`:

```markdown

\# не заголовок
\` не код
\[не ссылка\](не URL)
\\ обратный слэш
\| в таблицах
```

Экранировать нужно: `\ ` * ` _ ` # ` + ` - ` . ` ! ` { } ` [ ] ` ( ) ` |

## 📐 Лучшие практики

### Структура README.md
```markdown
# Название проекта

> Краткое описание в одну строку.

![Demo](demo.gif)

## Особенности
- ✨ Фича 1
- 🚀 Фича 2

## Установка
```bash
npm install my-package
```

## Использование
```javascript
import { foo } from 'my-package';
foo();
```

## Документация
Подробнее в [docs/](docs/).

## Лицензия
MIT © [Ваше имя]
```

### Правила хорошего тона
1. **Заголовок 1 — один** на документ.
2. **Пустые строки** вокруг блоков кода, списков, таблиц.
3. **Без более 6 уровней** заголовков.
4. **Таблицы** — не слишком широкие (для мобильных).
5. **Изображения** — с alt-текстом (для доступности).
6. **Ссылки** — осмысленный текст, не «тут»/«здесь».
7. **Списки** — согласованный маркер (либо `-`, либо `*`).
8. **Код** — указывайте язык для подсветки.
9. **Длинные строки** — некоторые предпочитают 80 символов, другие — одно предложение на строку.
10. **Line ending** — LF (Unix), не CRLF.

## 🪤 Частые ошибки

1. **Вложенные списки** — отступ должен быть 2 или 4 пробела (зависит от flavour).
2. **Список внутри списка** — пустая строка перед вложенным не всегда нужна.
3. **Таблицы** — требуют заголовок и разделитель `|---|`.
4. **Код в списке** — отступ 8 пробелов (или 4, если список с `-`).
5. **`#` без пробела** — `#заголовок` не сработает, нужно `# заголовок`.
6. **Ссылки с пробелами** — `[текст](url с пробелом)` сломается.
7. **HTML-блоки** — должны быть отделены пустыми строками.
8. **Underline `_` в словах** — `my_var_name` может стать курсивом.
9. **End-of-line 2 пробела** — для переноса часто забывают.
10. **Emojis** — не везде поддерживаются (терминал, PDF).

## 💡 Полезные советы

1. **README.md** в корне проекта — первое, что видят на GitHub.
2. **Изображения** — в отдельную папку `docs/` или `assets/`.
3. **Оглавление (TOC)** — для длинных документов.
4. **Badges** (shields.io) — для статусов CI, версий, лицензий.
5. **`<details>`** — для сворачивания длинных логов/конфигов.
6. **Mermaid** — для диаграмм прямо в markdown.
7. **Pandoc** — для конвертации в PDF/DOCX/HTML.
8. **markdownlint** — для единообразия в команде.
9. **Alt-текст** у изображений — для доступности.
10. **Один h1** — для SEO и структуры.
