🐘 SQL — трюки и оптимизации (PostgreSQL / Greenplum)#

🧹 Очистка данных (Data Cleaning)#

Нормализация Unicode (диакритики):

-- Привести акцентированные символы к ASCII
translate(column,
    'áéíóúàèìòùãẽĩõũâêîôûäëïöüçñ',
    'aeiouaeiouaeiouaeiouaeioucn'
);

-- Удаление всех не-ASCII символов
regexp_replace(column, '[^\x00-\x7F]+', '');

💡 Подробнее: коллации (collation) в БД влияют на сортировку — одни и те же данные могут сортироваться по-разному в зависимости от LC_COLLATE.

Конвертация часовых поясов:

-- Явное преобразование с tz-колонки
SELECT timestampz_column AT TIME ZONE 'Europe/Moscow';

-- Если временная зона указана не всегда
coalesce(
    try_cast(timestamp_column AS timestamp with time zone),
    timestamp_column::timestamp AT TIME ZONE 'UTC'
)

Удаление спецсимволов:

-- Только буквы, цифры и пробелы
regexp_replace(column, '[^a-zA-Z0-9\s]', '');

-- Удаление конкретных символов
translate(column, '[]{}()*#$%@!?+=/\|', '');

Приведение булевых значений к стандарту:

case
    when lower(column) in ('1', 'yes', 'true', 'y', 't')  then true
    when lower(column) in ('0', 'no', 'false', 'n', 'f')  then false
    else null
end as bool_column

⚡ Оптимизации запросов#

Замена тяжёлого GROUP BY на WINDOW-функции (скоринг):

-- БЫЛО: подзапрос с GROUP BY + обратный join
-- СТАЛО:
SELECT * FROM (
    SELECT t.*,
           ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY date DESC) AS rn
    FROM t
) x WHERE rn = 1;

Классический Pivot через FILTER (PostgreSQL/Greenplum):

-- БЫЛО: нагромождение CASE WHEN
-- СТАЛО: чище и быстрее
SUM(value) FILTER (WHERE metric = 'clicks')    AS clicks,
SUM(value) FILTER (WHERE metric = 'opens')     AS opens,
SUM(value) FILTER (WHERE metric = 'delivered') AS delivered

Unpivot через LATERAL CROSS JOIN:

-- БЫЛО: 3× UNION ALL
-- СТАЛО: таблица читается 1 раз
SELECT t.user_id, x.metric, x.val
FROM metrics t
CROSS JOIN LATERAL (VALUES
    ('sent',     t.sent),
    ('deliv',    t.delivered),
    ('opened',   t.opened)
) AS x(metric, val);

NULLS LAST в ORDER BY ... DESC:

ORDER BY val DESC NULLS LAST;

По умолчанию в Postgres/Greenplum при DESC NULL’ы вылетают первыми, ломая топ-10 метрик приложения.

⚠️ SQL-грабли (даже для сеньоров)#

  1. = NULL никогда не true — используйте IS NULL / IS NOT NULL (трёхзначная логика: true, false, unknown).
  2. NOT IN (...) + NULL в списке может вернуть 0 строк. Безопаснее NOT EXISTS.
  3. LEFT JOIN + фильтр в WHERE превращается в INNER JOIN. Фильтры по правой таблице кладите в ON.
  4. COUNT(col) пропускает NULL, а COUNT(*) — нет. Метрики «магически» не сходятся.
  5. NULL ломает конкатенацию и сравнения — используйте COALESCE осознанно.

🎣 SQL-задача с подвохом: «последний заказ оплачен»#

Найти пользователей, у которых последний заказ был оплачен.

-- orders: id | user_id | status | created_at
-- user 10: paid(01-01) → cancelled(01-05)  ← последний cancelled!

❌ Неверно — фильтр WHERE status='paid' срабатывает до ROW_NUMBER():

WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (
        PARTITION BY user_id ORDER BY created_at DESC) AS rn
    FROM orders
    WHERE status = 'paid'          -- ← отсёк cancelled слишком рано
)
SELECT * FROM ranked WHERE rn = 1; -- user 10 попадёт, хотя не должен

✅ Правильно — сначала последний заказ вообще, потом проверка статуса:

WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (
        PARTITION BY user_id ORDER BY created_at DESC, id DESC) AS rn
    FROM orders
)
SELECT * FROM ranked
WHERE rn = 1 AND status = 'paid';

Порядок фильтрации в SQL полностью меняет смысл запроса.

📊 SAS — PROC SQL с внешней БД#

options msglevel=i;
proc sql _method _tree;
    /* Сессия к СУБД (например, Oracle) */
    connect to oracle as my_db (user=base_user password=XXXXX path=prod_db);

    /* Тяжёлый расчёт на стороне БД */
    execute (
        CREATE TABLE tmp_campaign_pre_target AS
        SELECT client_id
        FROM customer_table
        WHERE active_flg = 'Y'
    ) by my_db;

    /* КРИТИЧНО: рвём сессию, чтобы не висела «зомби» в СУБД */
    disconnect from my_db;
quit;

📧 Маркетинговые коммуникации (CMO-системы)#

  • Динамические шаблоны писем — работают; ключ задачи, например BDM_6737.
  • Динамическая дата в коммуникации:
  • Проблема: вместо 12.05.2026 подставляется 2026-05-12.
  • Решение: to_char(поле_даты, 'dd.mm.yyyy'). Но to_char в CMO может быть скрыт по умолчанию — снимите флажок «Валидация формул», и оно работает.
  • Отчёт: «сколько каждый юзер в среднем получил коммуникаций в месяц» от БС.
  • Идеи автоматизации:
  • Брать названия макетов из Confluence и генерировать скрипт проверки раскатки/откликов.
  • Чекать коммуникации с одним макетом и count >= 15 000 000.

🐉 CachyOS — установка и восстановление загрузчика#

Шаг 0. Подготовка (Live USB)#

# 1. Синхронизация времени
sudo timedatectl set-ntp true

# 2. Самые быстрые зеркала
sudo cachyos-rate-mirrors

# 3. Обновить ключи и базы ОДНИМ запросом
sudo pacman -Sy archlinux-keyring cachyos-keyring --needed

# 4. Зарегистрировать ключи в системе
sudo pacman-key --populate archlinux cachyos

# 5. Установить Calamares
sudo pacman -S calamares cachyos-calamares-config cachyos-hooks --needed

Шаг 1. Удаление записи из NVRAM (BIOS/UEFI)#

# Список загрузочных записей
sudo efibootmgr
# Boot0001* CachyOS   Boot0002* Windows Boot Manager ...

# Удалить ненужную (XXXX — 4-значный номер, например 0001)
sudo efibootmgr -b XXXX -B

⚠️ Будьте предельно внимательны — не удалите загрузчик Windows или другой важной системы.

Шаг 2. Удаление файлов с ESP-раздела#

lsblk                                   # найти ESP (FAT32, ~500MB–1GB)
sudo mount /dev/sdXY /mnt               # примонтировать
ls /mnt/EFI/                            # убедиться что удаляете нужное
sudo rm -rf /mnt/EFI/CachyOS

Шаг 3. Чистка записей systemd-boot#

cd /boot/loader/entries/
ls -l                                    # файлы *.conf
# открыть каждый и проверить, что пути/разделы существуют
# удалить «битые»:
sudo rm имя_файла.conf
sudo bootctl update                      # перечитать структуру

После установки#

  1. Проверить, что всё обновлено через pacman и загрузка идёт через зеркала.
  2. Сразу установить весь софт hypr-стека / окружения.

🐍 Python — обработка исключений#

Исключение — событие при ошибке. Не обработано → программа падает.

try:
    age = int(input("Сколько вам лет? "))
    print(f"Через год вам будет {age + 1}")
except ValueError:
    print("Ошибка: нужно ввести целое число!")

Несколько типов + else + finally:

try:
    num = int(input("Число: "))
    result = 100 / num
except ValueError:
    print("Это не число!")
except ZeroDivisionError:
    print("Делить на ноль нельзя!")
else:
    print(result)              # если ошибки не было
finally:
    print("Выполнится всегда") # закрытие ресурсов

⚠️ Голый except: — плохая практика: ловит вообще всё, включая KeyboardInterrupt (Ctrl+C). Ловите только ожидаемые исключения.

Мини-задача: запросить 2 числа, разделить, обработать ValueError и ZeroDivisionError, в finally вывести «Попытка деления завершена».

🐍 Python — работа с датами (datetime)#

from datetime import date, time, datetime, timedelta

now = datetime.now()          # 2026-07-20 14:30:45.123456
today = date.today()          # 2026-07-20
d = date(2026, 7, 20)         # создать дату
dt = datetime(2026, 7, 20, 14, 30, 45)

# Части даты
dt.year, dt.month, dt.day, dt.hour, dt.minute
dt.weekday()                  # 0 = понедельник

# Форматирование в строку
dt.strftime("%d.%m.%Y")       # '20.07.2026'
dt.strftime("%H:%M:%S")       # '14:30:45'
dt.strftime("%A, %d %B %Y")   # 'Monday, 20 July 2026'

# Парсинг строки → datetime
datetime.strptime("20.07.2026", "%d.%m.%Y")

# Арифметика (timedelta)
next_week = now + timedelta(days=7)
delta = datetime(2027, 1, 1) - now
delta.days, delta.seconds

Основные коды формата: | Код | Что | |—|—| | %Y / %y | Год 4 / 2 цифры | | %m | Месяц (01–12) | | %d | День (01–31) | | %H / %M / %S | Час / мин / сек | | %A | День недели (полностью) | | %B | Месяц (полностью) |

💡 Полезные советы#

  1. Порядок фильтрации в SQL меняет смысл запроса — фильтруйте на нужном шаге.
  2. FILTER (WHERE ...) чище и быстрее нагромождения CASE WHEN.
  3. LATERAL CROSS JOIN заменяет множественный UNION ALL для unpivot.
  4. NULLS LAST в ORDER BY DESC — спасает топ-N отчёты.
  5. COALESCE / NULLIF / IS NULL — три кита работы с NULL.
  6. to_char в CMO может быть скрыт — снимайте «Валидацию формул».
  7. disconnect в SAS — обязательно рвите сессию к БД, иначе «зомби».
  8. Исключения в Python — ловите конкретные, не голый except:.
  9. strftime/strptime — формат должен точно соответствовать строке.
  10. CachyOS — после установки проверьте зеркала и обновления до настройки окружения.

🩺 Медицина: тинитус, ВНЧС, нейропатия (заметки)#

Заметки собраны из открытых источников (Пикабу, Хабр и др.). Не являются медицинской рекомендацией — для ознакомления.

Постановка проблемы#

Тинитус (звон в ушах) + гиперакузия (тяжёлое восприятие обычных звуков, отдающее звоном и дребезгом). Длительный анамнез, множественные попытки лечения.

Гипотезы (от ЛОРа)#

  1. Вазоневральный конфликт — нерв соприкасается с артерией в голове. - Подтверждён на ~80% по МРТ мозга. - Решение (в теории): прокладка между конфликтующим нервом и артерией (микрососудистая декомпрессия) — вопрос к нейрохирургам.
  2. Дисфункция височно-нижнечелюстного сустава (ВНЧС) — часто бывает из-за отсутствия задних зубов, на которых держится прикус. - Решается с гнатологом, но долго и без гарантии — как фоновая задача.

Зацепка: нейропатия стременного нерва#

Исследование КСВП (коротких вызванных потенциалов коры мозга) и стволовых акустических вызванных потенциалов показало «нейропатию стременного нерва» — редкую, но первую конкретную зацепку. Может давать как звон (тинитус), так и гиперакузию. Дальше — к отоневрологу (хорошие специалисты редки, очередь может быть 2–2.5 месяца и более; в Питере к топовым — до 1.5–2 лет).

Упражнение: изолированное укрепление глубоких сгибателей шеи (усиленная версия)#

Лёжа на спине: 1. Подбородок чуть к груди (минимально!). 2. Поднять голову на 1–2 см, не напрягая поверхностные мышцы. 3. Удерживать 7–10 секунд. 4. Отдых 5 сек. 5. Повторить 10 раз.

Зачем: снижает компрессию в зоне C2–C5 → шум уменьшается через 7–14 дней.
